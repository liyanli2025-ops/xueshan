# 翻越夹金山 · 互动 H5

1935 年 6 月 12 日，中央红军红一军团二师四团从硗碛出发，翻越长征途中第一座大雪山。
本页所有情节、台词均取材于真实史料，出处见页面右下角「史料」浮层。

## 运行

纯静态页面，无构建、无依赖。用任意静态服务器打开 `snow-march-final-v3.html` 即可。
直接双击本地文件也能跑，但部分浏览器会限制 `file://` 下的视频加载，建议走 HTTP。

## 关键实现约定

改动这个页面前，请先了解以下几条——都是踩坑换来的：

1. **布局按设计稿 1280×720 写固定像素**，整体 `scale(var(--fit))` 等比缩放。
   页面内不出现任何 `vw` / `vh` / `clamp()`。手机和 PC 的差别只有 `--fit` 这一个系数。
2. **字号按「手机上的实际大小」定**。手机横屏 `--fit ≈ 0.54`，
   正文设计稿 ≥34px、次要信息 ≥26px，才能保证手机上分别有 18px / 14px（面向老年读者）。
3. **强制横屏靠旋转 `body`，不弹提示**。竖屏时 `@media (orientation: portrait)` 把整个
   `body` 旋转 90 度。必须转 `body`——`.prologue`、`.archive` 都是 body 的直接子元素。
4. **字幕由视频的 `currentTime` 驱动**，不用 `setTimeout`。墙钟在视频缓冲时会跑到画面前面。
5. **要让某一层退场，用一次性开关**，不要列举 `.app.is-xxx` 状态——迟早会漏掉一个。
6. **字体内嵌，不依赖系统字体**。`FangSong` / `KaiTi` 只有 Windows、macOS 有，
   iOS 缺仿宋、Android 两个都没有，同一页面在三端会长出三个样。
   现内嵌两款开源字体的子集（370 KB）：霞鹜文楷用于标题与台词，朱雀仿宋用于正文与界面。
   **改动文案后要重新生成子集**，否则新字会显示成豆腐块：

   ```bash
   pyftsubset LXGWWenKai-Medium.ttf --text-file=chars.txt --flavor=woff2 \
     --layout-features='' --output-file=assets/fonts/kai-subset.woff2
   ```

7. **长按交互必须禁掉 iOS 文本选择**：`-webkit-touch-callout`、`-webkit-user-select`、
   `touch-action: none` 三个都要写，否则长按会震动并弹出「拷贝」菜单。
8. **正片使用三个常驻 video 元素轮换**：当前段播放时，另外两个元素分别预加载后面的
   `+1`、`+2` 段；页面初次打开时即优先预加载 `01`—`03`。不要改回临时 video；临时元素
   失去引用后可能被浏览器回收，导致每次切段重新加载。切换时若下一段仍未就绪，应保留上一帧，
   不显示通用加载提示；只有当前播放段真正加载失败时才提示错误。
9. **开场只保留一次点击**：史实序幕点击“继续”后，片名卡停留 3.2 秒并自动进入正片。
   片名在点击前必须保持隐藏，且片名卡内不再设置二次进入按钮。该次点击会同步预载并解锁前三段
   video，避免移动端阻止定时触发的自动播放；第 `01` 段可播放后再退掉片名背景，不能露出缓存槽。
10. **人物台词卡优先控制在两行正文内**：说话人标题单独一行，台词正文使用横屏可用宽度自然折行；
    不要在台词字符串中依赖人工换行控制版式。
11. **自动视频必须完整播放后直接续接**：不得提前截断尾帧，也不对视频层使用淡入淡出、交叠、白场或
    其他转场效果；下一段首帧提前解码，上一段触发 `ended` 后立即切换。只有抓住木棍、长按行进和拉人
    等剧情交互可以暂停。
12. **正式播放前必须完整缓存全部正片文件，不只设置 `preload="auto"`**：页面打开后立即通过
    `fetch` 下载全部 6 个连续播放文件并生成 Blob URL；未全部成功时只停留在片名卡显示总体准备进度。正片开始后
    不再发起视频网络请求；已经播完且完成淡出的 Blob 会逐段释放，避免移动端内存持续增长。
13. **山脚地点卡跨段展示**：第 `01` 段出现后延续至第 `02` 段前 3 秒，利用下一幕左上角空位完成阅读。
14. **不以字幕或普通剧情段作为视频切换点**：`01—05` 合并为 `sequence-01-05.mp4`，
    `09—10A—10B` 合并为 `sequence-09-10B.mp4`。字幕只按长视频时间轴叠加；只有 06、07、09 的
    既定交互节点允许暂停或切换播放器。
15. **合并视频不能吞掉原有交互**：`sequence-01-05.mp4` 播到 `5.95s` 时暂停并显示“点一下，接过辣椒”；
    第 06 段暂停时必须以 `is-steps` 状态强制显示长按按钮，严禁出现没有操作提示的静止画面。
16. **长按事件必须绑定开始时的场景与 video 元素**：场景切换时立即取消旧的 hold 状态和动画帧；
    后到达的 `pointerup` 只能暂停原视频，严禁误暂停已经开始播放的下一段。
17. **切出页面后返回要恢复普通剧情**：仅当切出前视频确实在播放时记录恢复标记；返回后，
    若当前不是点击、长按、史料或尾声节点，立即续播。不得把一次标签页切换变成永久暂停。
18. **网页播放源采用轻量 WebM，并保留 H.264 回退**：浏览器支持 VP9 时优先读取
    `media-clean/*.webm`，不支持时继续使用 `media-clean/*.mp4`。所有正式视频仍须在片名卡阶段完整下载，
    正片开始后不依赖边播边加载。
19. **交互段不得先播放再暂停**：06 与最后拉人段切入时直接解码并展示首帧，不等待 `play()`
    Promise；按钮随首帧同时出现。后续段只提前缓存和解码，不得提前切换画面。
20. **第 07 段点击后完整播放当前视频**：完成“抓住木棍”后恢复播放，直到自然结束才接 08A；
    播放器切换不得等待 `play()` Promise，也不得用提前切走来规避尾帧等待。
21. **第 06 段的长按入口不得等待首帧解码**：场景一进入就显示按钮；若用户在视频就绪前已经
    按住，记录该动作并在播放器准备完成后立即开始行进。底部无叙事作用的分段进度条已整体删除。
22. **可见播放器禁止异步换源**：视频停在交互点时也属于可见状态，后台 Blob 下载完成后不得对它
    再执行 `load()`，否则画面会退回 0 秒而提示仍留在原时间点。第 07 段按实际动作改在 `4.15s`
    暂停，此时木棍已递到手中。
23. **退场层与预载层必须隔离**：淡出中的 video 标记为 `retiring`，完成前不得复用来加载未来视频；
    每次异步切场携带唯一 token，过期任务不得重新激活旧画面。当前活动层固定置于最高视频层级。
24. **08A → 09 不得提前切走**：08A 必须完整播完，随后直接切入已经缓存并解码的 09 首帧；
    拉人按钮必须等 09 首帧成为活动画面后再显示，交互接管时不得再次写 `currentTime = 0`。
25. **多行字幕必须保留人工换行**：`.beat-caption` 使用 `white-space: pre-line`，避免 `\n` 被折叠成
    普通空格后再次自动折行；同时使用 `width: max-content` 按最长一行自然撑宽，并以 `1100px` 封顶。
    单屏字幕优先控制在两行，不得在画面左右仍有空间时把句尾单独挤成第三行。确认能完整容纳的短句
    可配置 `singleLine: true`，以 `.is-single-line` 禁止中文逐字换行。
26. **交互指令前先交代人物状态**：第 06 段切上首帧后，先以暂停画面的呼吸起伏配合
    “风雪越来越大 / 他已经跟不上队伍”，约 `1.75s` 后再显示“按住 / 跟上队伍”。
27. **长按完成必须早于摔倒**：第 06 段进度环以视频 `6.9s` 为完成点，按钮随后退场，
    视频继续自动播放；人物约在 `7.8s` 开始失力，让“操作已经完成”与“最终仍然倒下”形成落差。
28. **正文不提供史料点击入口**：人物署名只作为普通文字显示，不加下划线、焦点或点击热区；
    全页统一通过右侧固定“史料”按钮打开史料面板，避免正文区域误触。
29. **云开必须有完整的情绪与视觉过渡**：在 `15.65s` 加入杨成武“岂不成了神仙”的鼓动，
    笑声后再交代云散；`20.4s—24.9s` 以 `is-glare` 让雪面逐步过曝，随后亮光退去、天色转暗。
30. **接辣椒的提示圈必须落在辣椒簇上**：热点使用成片 `1280×720` 坐标 `(530, 484)`；
    透明点击范围与可见圆环共用中心定位，调整位置时不得只移动伪元素或只移动点击盒。
31. **实物交互必须分别定位**：抓木棍热点使用成片坐标 `(365, 400)`，对准第一视角手掌与
    木棍的交接处；热点不得使用视口百分比，统一跟随固定舞台等比缩放，切换场景时同步清除旧目标。
32. **拉人段使用独立修正版视频**：`09-pull-fixed.mp4` 播放至约 `3.75s` 完成长按，第一视角
    右手全程握住木棍；完成后按钮直接退场，不显示“拉起来了”。修正版播完后，原连续尾段必须
    从 `0s` 完整播放“继续站起—站稳—自然松手—镜头抬起”，再越过垭口和下滑；不得把拉人成功
    后的动作当作错误片段一并跳过。
33. **顶部时间轴由视频播放时间逐帧驱动**：每个连续剧情段配置起止进度，普通播放时平滑前进；
    点击或长按交互使视频暂停时，时间轴同步停住，继续播放后从原位置续走。禁止在换场、字幕出现
    或长按完成时直接跳到下一节点，也不得由交互进度重复改写全片时间轴。
34. **恢复原版字体并补齐子集**：正文继续使用朱雀仿宋，标题和人物台词继续使用霞鹜文楷；两份
    `.woff2` 均从官方源字体按页面当前全部汉字与标点重新生成，不再缺少后加文案的字形。PC 与移动端
    加载相同内嵌文件，不依赖设备字体，也不得在同一句中逐字回退。
35. **正片使用纯音效音轨**：六个实际播放文件均以 DnR 三轨模型分离背景音乐，只保留风雪、脚步、
    呼吸和动作声；MP4 与 WebM 必须同步替换，避免不同浏览器选源后听到不同版本。
36. **风声环境底音贯穿全片**：页面先主动尝试播放 `audio/wind-background-loop.mp3`；若浏览器
    拦截有声自动播放，则在摘要页显示“轻触开启风声”，首次触碰后以 `1.2s` 渐入。源音频已移除
    头尾静音，并将尾部与下一轮开头交叉淡化 `1.4s`，循环时不再出现空档。视频切换及剧情交互
    不打断风声，手动关闭声音时以 `0.6s` 淡出，页面进入后台时暂停、返回后渐入恢复。
37. **摔倒声先于回头动作**：08A 在 `5.35s` 播放一次 `audio/fall-impact.mp3`，随后镜头约在
    `5.7s` 开始转身，`6.3s` 再出现“身后忽然一声闷响”的文字；音效只触发一次并跟随全局声音开关。
38. **喘气声只存在于长按等待状态**：06 进入暂停画面时循环播放 `audio/panting-loop.mp3`。素材
    响度约 `-25.3 LUFS`，播放音量设为 `44%` 后约为 `-32.4 LUFS`，与后续行进视频中的喘气声
    基本一致。等待时以 `0.42s` 渐入，开始长按时以 `0.32s` 渐出；中途松手会继续喘气，长按完成、
    切换场景或页面进入后台后立即停止。

## 视频兼容性

`media-clean/` 同时提供 H.264/AAC MP4 和 VP9/Opus WebM，可用于 Chrome、Safari、Firefox
及主流 Android / iOS WebView。页面使用 `object-fit: cover` 统一填充 16:9 舞台。
